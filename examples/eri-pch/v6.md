# eri-pch_v6 — significant shell pairs only

v1..v5 enumerate every (s1, s2) shell pair with s1 ≤ s2, so the AO-pair
dimension is

    P = sum over (s1<=s2) of n(s1) * n(s2)        (with i<=j when s1==s2)

i.e. ~`N_shell² · n²/2`. For an extended molecule the matrix
M = (μν | αβ) blows up quadratically with the number of shells even
though its physically non-negligible block grows only linearly. v3..v5
mitigate the cost in the *kernel* (libint2's per-quartet primitive
screening drops integrals that round to zero) but they still pay for
the layout — `pairs[]`, `pair_lookup[]`, the diagonal scan, and every
`compute_slab` task fan-out are all sized at the unscreened P.

v6 fixes the layout itself. Before populating `IntegralData`, the shell
pairs are filtered by overlap norm (the same notion libint2's
`hartree-fock++.cc::compute_shellpairs` uses):

```cpp
auto sps = compute_significant_shellpairs(basis, threshold);
// keep (s1, s2) iff:
//   - s1 and s2 are on the same atom (always significant), or
//   - || S(s1, s2) ||_F  >=  threshold
```

The TTG graph is otherwise byte-identical to v5; the only change is the
input data. The screened M is what gets decomposed and what
`validate_decomposition` reconstructs against, so the residual check
remains apples-to-apples.

## Threshold

Default 1e-12 (matches the libint2 hartree-fock++ default in
`compute_shellpairs`). Override with the env var
`TTG_ERI_PCH_SP_THRESHOLD`. Setting it to 0 disables screening and
reproduces v5 exactly.

## Why overlap norm

For a Cholesky decomposition with tolerance τ, the algorithm itself
drops below-τ pivots, so an unscreened run wastes work but does not
lose accuracy. The overlap-norm test is a cheap upper-bound proxy: a
shell pair whose overlap block has Frobenius norm below τ_overlap
contributes ~τ_overlap²-ish magnitude to the diagonal of M, and
1e-12 is well below typical Cholesky tolerances (1e-6 to 1e-8). A
Schwarz-norm (sqrt(||(s1 s2 | s1 s2)||_∞)) test would be tighter
but requires an ERI compute per shell pair instead of an overlap
compute; for the sizes this example targets the overlap test is
already accurate enough.

## Build & run

```sh
ninja -C cmake-build-relwithdebinfo eri-pch_v6-parsec
./examples/eri-pch_v6-parsec [molecule.xyz] [basis] [tol]

# tighter threshold
TTG_ERI_PCH_SP_THRESHOLD=1e-10 ./examples/eri-pch_v6-parsec ~/tmp/c6h6.xyz def2-tzvp

# disable screening (= v5)
TTG_ERI_PCH_SP_THRESHOLD=0     ./examples/eri-pch_v6-parsec ~/tmp/c6h6.xyz def2-tzvp
```

On startup, rank 0 prints

```
[eri-pch] shell-pair screening: threshold = 1.00e-12; kept K of N shell pairs (P AO pairs)
```

so the screening-effectiveness ratio K/N is visible in the run log.

Side effects: writes the TTG flow graph to `eri-pch_v6.dot`. Other
env vars (`TTG_ERI_PCH_CHUNKS`, `TTG_ERI_PCH_TRACE`) carry over from
v5 with the same meaning.
