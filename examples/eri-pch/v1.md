# eri-pch_v1 — bulk-synchronous TTG dispatch with C++ outer loop

Integral-direct pivoted Cholesky decomposition of the 4-center AO 2-electron
integral matrix following Koch, Sánchez de Merás & Pedersen, *J. Chem. Phys.*
**118**, 9481 (2003). Integrals via libint2; per-thread engine cache.

## TTG topology

Two **disconnected** sub-graphs, each a flat fan-out:

```
   invoke()  ─▶  drive_diag    ──Edge<size_t,void>──▶  compute_diag(sp_idx)
                   (void)                                  (writes d[sp])

   invoke()  ─▶  drive_pivot   ──Edge<size_t,void>──▶  compute_pivot_block(sp_idx)
                   (void)                                  (writes Q[rows of sp])
```

The driver code in `run_cholesky()` keeps an outer `while (true)` C++ loop that
invokes the two pipelines in sequence:

```text
flow.run_diagonals();          // invoke drive_diag, fence
prescreen d[]; X_max from d
loop:
    pivot_p   = argmax(d)             // sequential, host
    if d[pivot_p] < tol:  break
    cur_pivot_sp = pairs[pivot_p].sp  // metadata
    Q.assign(P * W, 0)
    flow.run_pivot_block();    // invoke drive_pivot, fence
    while (sub_pivot in pivot_sp with d[sub] > X_max/1000):
        apply_cholesky_update(sub_pivot)   // sequential, mutates d, L
```

Each `flow.run_*()` is one `invoke() + ttg::fence()` pair — bulk-synchronous.

## Shared state

`CholeskyDriver` carries everything by reference into the lambdas:

- `d[]`           — running diagonals; written by `compute_diag` (disjoint
                     slices) and `apply_cholesky_update` (sequential).
- `L[][]`         — finished Cholesky vectors; appended by
                     `apply_cholesky_update` (sequential).
- `Q[]`           — `[P × cur_pivot_npairs]` column block for the current
                     pivot shell pair; written by `compute_pivot_block`
                     (disjoint row strips).
- `cur_pivot_sp`  — set by the C++ driver before each `run_pivot_block()`,
                     read by the per-shell-pair task.

Disjoint-write invariants make explicit synchronization unnecessary; the
fence between phases handles cross-phase ordering.

## What's TTG-parallel and what isn't

| Step                                    | Where it runs                |
|-----------------------------------------|------------------------------|
| Initial diagonal compute                | TTG fan-out (parallel)       |
| `argmax(d)`                             | sequential (driver thread)   |
| Per-iter pivot-block integral compute   | TTG fan-out (parallel)       |
| Sub-pivot selection within a shell pair | sequential                   |
| L-vector formation & d[] update         | sequential per sub-pivot     |
| Iteration sequencing                    | C++ `while` loop with fence  |

## Strengths

- Smallest cognitive footprint — easy to read, easy to map back to the paper.
- No serialization overhead: nothing flows through edges except control tokens.
- The TTG graph is trivial to anchor (`make_graph_executable` on each driver root).

## Weaknesses

- A `ttg::fence()` between every iteration. For small molecules this dominates
  wall time; for water/def2-svp (~65 outer iters) it's most of the runtime.
- No overlap between iterations: integrals for iteration N+1 cannot start
  until iteration N has fully completed its sub-decomposition.
- The graph in `eri-pch_v1.dot` only depicts the within-iteration parallelism
  — the outer loop is invisible because it lives in C++.

## Build & run

```sh
# from a configured build directory:
cmake --build . --target eri-pch_v1-parsec
./examples/eri-pch_v1-parsec [molecule.xyz] [basis] [tol]

# defaults: water (experimental geometry), def2-svp, 1e-8
./examples/eri-pch_v1-parsec
```

Side effects: writes `eri-pch_v1.dot` (TTG graph in GraphViz format).

## Reference numbers (water, single rank)

| Basis    | Tol    | P   | Rank | Ref rank | max err  |
|----------|--------|-----|------|----------|----------|
| sto-3g   | 1e-8   | 28  | 28   | 28       | 3.3e-16  |
| cc-pVDZ  | 1e-8   | 300 | 251  | 248      | 7.2e-9   |
| def2-svp | 1e-8   | 300 | 251  | 246      | 7.8e-9   |
| def2-svp | 1e-10  | 300 | 276  | 276      | 7.7e-11  |

`Ref rank` is `libint2::pivoted_cholesky` on the dense ERI matrix. Koch's
shell-blocked algorithm overshoots the fully-greedy rank by a few vectors
because it commits to one pivot shell pair at a time.
